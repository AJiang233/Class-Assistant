# 文案规范

面向用户的中文文案（页面标题、按钮、表单标签、提示语、空态、浏览器标题…）的统一口径。

新增或改动文案前对照本表；发现新的不一致，**直接改到这张表里**——表是活的，不是摆设。
适用范围：`web/` 下的 HTML 与 JS。原生端（`android/`、`HarmonyOS/`）与后端返回的提示语
尚未纳入，见文末「待收敛」。

## 1. 术语表：同一个东西只有一个叫法

| 概念 | 统一叫法 | 不要写成 |
| --- | --- | --- |
| 班级通知模块 | 班级通知 | 通知、通知中心 |
| 班级活动模块 | 班级活动 | 活动、活动中心 |
| 课表 + 学业达成模块 | 课表与学业 | 教务、课程表 |
| 学业达成那一块 | 学业达成 | 学分达成、学分看板 |
| 课表里没排时间的课 | 未安排课程 | 未排课程 |
| 待填写的表单 | 表单 / 待填表单 | 问卷、表格 |
| 一条内容的作者 | 发布人 | 通知人、创建人 |
| 会被提醒的人 | 提醒对象 | 被通知人、接收人 |
| 班级里的身份（班长、团支书…） | 职位 | 职务、角色 |
| 通知 / 活动的有效期 | 截止时间 | 存活至、过期时间 |
| 手机 App 之外的那一端 | 网页版 | Web 端、浏览器版 |

## 2. 按钮与动作

- **编辑类**一律「编辑」，不用「修改」——列表行、弹窗标题、提交按钮都统一
- **保存类**主按钮一律「保存」（改密码表单也是「保存」，表单标题已说明改的是什么）
- **查看入口**一律「查看全部」，不用「全部活动」「查看更多」
- **二次确认**用「确定…？」+「确定 / 取消」两个按钮，不用「关闭」「好的」
- **创建类按对象定动词**，且同一个对象在标题与按钮上必须同一个词：
  发布通知 / 发布活动 / 添加表单 / 添加成员 / 添加职位
  （反面例子：卡片标题写「添加成员」，按钮却写「注册成员」）

## 3. 标点与格式

- 中文里的括号一律**全角**「（）」，错误提示里的状态码也放进去：`请求失败（500）`
- 并列用顿号「、」，不用半角斜杠串中文；**例外**：搜索框占位用「 / 」分隔检索维度，
  如 `搜索姓名 / 学号 / 职位`
- 分隔信息用「·」，如「发布人 张三 · 09-14 10:00」
- 省略号用「…」，不写三个点
- 需要用户输入半角符号的字段，提示里写明是「**英文**逗号」，不要只说「逗号」
- 中文单位不加空格（`2 分钟`）；不要中英单位混排（写 `30 秒`，不写 `30s`）

## 4. 状态与反馈

- **内容区占位**：「正在加载…」（统一走 `stateHTML('正在加载…')`）
- **按钮进行态**：「保存中…」「提交中…」——按钮上不写「正在…」（太长）
- **空态**要说清「为什么空」，不要只写「暂无数据」：
  - 「今天没有安排」
  - 「还没同步到课表。到「课表与学业」绑定教务系统后会自动同步」
  - 「今天暂无安排」（今日活动为空，但那是正常状态，不是缺数据）
- **错误态**一句话说清「发生了什么 + 我该做什么」：
  - 「教务登录态已过期，当前显示的是上次同步的课表 · 课表有变动时请点「刷新」」
- **常态提醒不要用红色横幅**：教务登录态过期、缓存数据这类「不是错误、只是说明」的情况，
  用一行小字（`.ac-alert.ac-hint`），红底横幅留给真正出错的时候

## 5. 标题层级

- 浏览器 `<title>` 写成「页面名 - 班级助理」，页面名与页内 `h1`、侧栏 / 底部导航**完全一致**：
  `班级通知 - 班级助理`，而不是 `通知 - 班级助理`
- 例外：没有固定页名的页面（如 `forms.html`，页内标题是动态的表单名）用用途做页面名：
  「填写表单 - 班级助理」
- 页内 `h1` 是模块名（「班级通知」），区块标题是内容名（「正在进行」「已经结束」），两者别互换
- iframe 的 `title` 属性（无障碍读屏用）同样写模块名

## 6. 语气

- 说人话，不堆「请」；错误提示不指责用户（「学号或密码不正确」，不写「你输入错了」）
- 只有数据丢失、不可逆操作才用重语气，并在确认框里写明后果
  （「删除后这条通知及其提醒都会消失」）
- 不拿「系统」当主语推卸责任（内测横幅那种整站公告除外）

## 待收敛（本次未改，下次改到相关页面时顺手统一）

- 改密码的提交按钮「确认修改」→ 建议「保存」
- 「注册成员」（按钮）vs「添加成员」（卡片标题）→ 建议都用「添加成员」
- 「创建」（添加表单的提交按钮）→ 建议「添加表单」
- 「已发送，请查看通知栏」vs「已发送，请查看手机通知栏」→ 二选一
- 「结果」vs「查看提交明细」（表单提交进度入口）→ 建议「查看提交明细」
- 后端返回的提示语（`web/backend/src/handlers/*.js`）与原生端文案尚未核查
