# 班务数据、投递与同步契约

本次升级将表单联动改为 D1 事务，把受众身份固定为用户 ID，并用持久发件箱和单调变更序号承接通知发送与 Android 同步。服务仍运行在 Pages / D1；定时投递单独运行在一个 Cron Worker。

## 接口契约

`remind_people` 写入值为正整数用户 ID 数组，也接受由数字字符串组成的数组。空数组或 null 表示全班，仍排除 `class:exclude` 成员；显式选中的成员不受排除组限制。姓名、无效 ID、布尔值和对象返回 400 / `INVALID_REMIND`。姓名只用于显示，改名不会改变已有名单。

通知和活动列表增加 `audience=mine`。SQL 先筛选受众及日期，再按时间与 ID 排序分页；响应增加 `nextOffset`，为 null 时结束。省略此参数保留全部台账语义。`/api/forms/mine` 也返回 `nextOffset`；首页自动加载全部个人分页。每页最多 100 行，偏移最多 10000，超过上限提示归档或缩小日期范围。

`GET /api/sync` 需要正常登录。首次或规则重建用 `?after=0&snapshot=1&limit=100`；响应仍包在 `{success:true,data:...}` 内：

```json
{"version":1,"rules":"受众规则摘要","until":123,"cursor":100,"hasMore":true,
 "changes":[{"seq":100,"kind":"notices","id":8,"deleted":false,"operation":"update","row":{"id":8,"title":"通知"}}]}
```

- `seq` 是独立自增序号，不随发布时间修改。`until` 是这一轮固定上界；后续页原样携带 `until`、`rules`，并以返回的 `cursor` 作为 `after`。
- 初始化所有页都携带 `snapshot=1`，只读取上界内各条目的最后版本。完成后下一轮省略 `snapshot` 与 `until`，继续携带 `after` 和 `rules`，获取增量。
- `deleted:true` 表示删除或不在受众内，客户端移除该项。形式为 `kind + id` 的复合键，三类 ID 不混用。
- 角色规则、用户职位、账号或协议规则变化返回 `{version:1,reset:true,rules:...}`；客户端丢弃本轮内存结果，从新快照重建。
- `row` 不下发表单答案、完整受众或其他人的提交名单；表单仅附当前用户的 `submitted` 状态。提交和覆盖也会推进同步序号。
- Android 收齐固定上界后，将快照、游标、待提醒项及活动投影放在同一次 SharedPreferences `commit()` 中持久保存。失败或账号已切换不提交。提醒成功后确认；进程中断重放使用相同通知 ID，并设置 `OnlyAlertOnce`。首次同步不补推历史，未来才生效的通知保留待提醒项。

## 数据库升级

统一入口是 Wrangler 官方迁移账本 `d1_migrations`，SQL 位于 `migrations-v2/`。`schema.sql` 是供测试及新库检查使用的快照，不要拿它覆盖已有库或逐次重跑。

支持的旧库基线为本仓库 2026-09-19 之后的表结构：包含用户邮箱及 `password_changed_at`、通知归属及链接、活动归属、表单与提交表。更早的数据库先对照 `migrations/` 补齐相应旧版迁移；其中 ALTER 语句不能盲目重复执行。升级前可通过 `PRAGMA table_info(users)`、`PRAGMA table_info(notices)`、`PRAGMA table_info(activities)` 核对基线。

从 `web/` 运行：

```powershell
npm ci
npm run db:local
# 验收完成后，维护窗口中运行线上迁移
npx wrangler d1 export class-assistant-db --remote --output=../.Codex/before-upgrade.sql
npm run db:migrate
```

新库也使用 `npm run db:remote`，它与 `db:migrate` 是同一个官方迁移入口。重复运行只会执行未登记的迁移，本地已验证第二次返回无待执行项。不要从旧版 `schema.sql` 导入后直接标记迁移完成。

迁移会将唯一匹配的旧姓名转为 ID。同名、失联姓名、旧逗号字符串及无法解析的值写入 `audience_migration_issues`，未匹配部分用保留值 0 表示，不会扩散成全班。管理员需要在编辑界面取消“未匹配的原名单”并重新选择。历史孤儿提交保存在 `orphan_submission_archive`，再从正式提交表移除；外键此后阻止新孤儿产生。先检查这两个表再完成上线验收。

表单删除通过外键级联清理答案和创建关联，触发器清理联动通知；删除用户清理订阅与验证码，已提交的答案按历史资料保留。业务创建、变更日志和发件箱登记在同一事务中，迁移历史只建立同步基线，不补发通知。

## 投递 Worker 上线

先迁移数据库，再发布 Pages 和新版 Android，最后启用独立投递 Worker。姓名名单写入是破坏性接口变更，旧客户端若仍传姓名会收到 400，必须随前端一并更新。

```powershell
# 以下命令都在 web/ 下执行，实际数据库 ID / SITE_ORIGIN 以部署环境为准
npx wrangler secret put EMAIL_API_KEY --config wrangler.delivery.toml
npx wrangler secret put VAPID_PUBLIC_KEY --config wrangler.delivery.toml
npx wrangler secret put VAPID_PRIVATE_KEY --config wrangler.delivery.toml
npx wrangler deploy --config wrangler.delivery.toml
```

Pages 的 Secrets 不会自动继承，邮件发件人及 VAPID subject 如有覆盖也要配置到该 Worker。业务邮件走此 Worker；验证码仍由 Pages 同步发送。使用 Workers 付费套餐的每次调用 1000 子请求额度：默认每轮展开最多 10 个事件、分 10 波发送最多 40 个目标，同波最多 4 路出网。不要将这个默认批量直接运行在 50 子请求限制的套餐上。

每个事件展开时固定逐渠道、逐目标的投递记录，重复展开由事务和唯一键收敛。发送前复核当前订阅、设备归属、邮箱与内容受众。租约 120 秒；超时可接管，旧消费者的确认不能覆盖新租约。网络故障、408、429、5xx 指数退避；其余 4xx 或累计 8 次失败进入 `dead`。缺渠道配置保留 `pending`，不消耗重试次数。Web Push 404/410 清理相同账号与密钥的旧订阅。

这是一套至少一次投递。邮件使用稳定 Resend 幂等键（服务商保留窗口内去重）；Web Push 使用稳定 tag，Android 使用稳定通知 ID。上游已接收、进程在确认前退出时，无法承诺端到端恰好一次。联动表单设备只推一次，邮件按表单与通知两类订阅各自发送。

排查积压和失败：

```sql
SELECT state, count(*) FROM outbox_deliveries GROUP BY state;
SELECT count(*) FROM outbox_events WHERE expanded=0;
SELECT id, event_seq, channel, attempts, last_error FROM outbox_deliveries WHERE state='dead';
PRAGMA foreign_key_check;
SELECT * FROM audience_migration_issues;
```

确认某条失败原因已消除后，按投递 ID 重放；不要批量重放所有历史记录：

```sql
UPDATE outbox_deliveries SET state='pending',attempts=0,next_at=0,lease_until=0,lease_token=NULL
WHERE id=需要重放的投递ID AND state='dead';
```

当前不自动清理变更日志，旧游标因此不会因保留期丢失。增量查询按序号索引扫描，初始化使用条目与序号复合索引查最后版本；随着班级历史增长应观察 D1 表大小及读取行数。未来压缩日志需要先增加最小有效游标和重建协议，不能直接删旧行。每个提交会记录一次表单投影及提交者 ID 集合，不包含答案；超大班级需评估这部分写入量。

## 回滚与本地验证

数据库升级包含表重建与受众转换。需要回滚时暂停写入及 Cron，恢复升级前导出，再恢复对应版本代码；只回退 Pages 会与新接口和触发器不一致。备份和运行时配置保留本地，不提交到仓库。本 PR 不执行线上迁移或部署。

```powershell
# 仓库根目录
npm --prefix web test
node .Codex/d1-smoke.mjs
# 中文目录可映射一个空闲盘符，以免 Java 测试工作进程误解码类路径
subst R: .
$env:ANDROID_HOME='R:\.Codex\android-sdk'
R:\android\gradlew.bat -p R:\android testDebugUnitTest assembleDebug '-Pandroid.overridePathCheck=true'
```

`d1-smoke.mjs` 读取 `.Codex/d1-review/v3` 的本地数据库，先在 `web/` 执行 `npx wrangler d1 migrations apply class-assistant-db --local --persist-to ../.Codex/d1-review`。Web 测试包含真实 SQLite、事务失败注入、租约接管、设备改绑、固定上界快照、状态序列模型及四项关键 SQL 变异验证。Android JUnit 使用真实 JSON 实现验证客户端协议，不依赖 mock Android 的 JSON 方法。
